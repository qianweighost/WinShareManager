# WinShareManager v2.1.1 发布说明

> 紧急修复版：v2.1.0 的 DLNA 启动必现崩溃，本版修复后 DLNA 可正常启用。

## 修复

### 1. 拨动 DLNA 开关即报错「Substring 索引和长度必须引用字符串内的位置」（关键修复）

- **现象**：v2.1.0 中点击 DLNA 卡片开关，服务无法启动，日志记录 `启动 DLNA 失败`；程序启动时的 DLNA 自动启动同样失败。
- **根因**：`Get-DlnaUuid` 生成设备 UUID 时，FNV-1a 哈希格式化出的十六进制串为 16 字符，UUID 需要 32 字符。补齐逻辑只追加了前 8 个字符（合计 24 位），而后续 `$hex.Substring(20, 12)` 需要访问到第 31 位，必然抛出 `ArgumentOutOfRangeException`。
- **修复**：整段复制十六进制串补齐到 32 位（`$hex + $hex`），UUID 五段分割（8-4-4-4-12）全部落在合法范围内，且格式符合标准 UUID。
- **影响**：v2.1.0 的 DLNA 功能完全不可用；v2.1.1 修复后拨动开关即可启动，电视 / 机顶盒 / 手机自动发现。

### 2. DLNA 卡片开关点击无响应（v2.1.0 构建内已含，随本版一并分发）

- 事件绑定循环 `@('SMB','WebDAV','FTP','SFTP')` 漏掉 `'DLNA'`，导致 DLNA 卡片的开关没有挂接点击事件；已补上，并新增「开关绑定」冒烟断言（新增协议卡片漏绑时自检直接报错）。

## 升级说明

- 从 v2.1.0 升级：直接用本版 exe 替换即可，配置（`C:\ProgramData\WinShareManager\config.json`）自动保留，无需重建共享。
- DLNA 端口默认 8420（若 8200 被其他程序占用请勿改回）。
- DLNA 协议本身无账号密码，勾选 DLNA 的目录对整个局域网只读，请注意内网环境。

## 已知问题

- `C:\Windows\SysWOW64\wrdlv4.exe` 占用 8200 端口且无法结束进程，建议用户自行排查该程序来源（本工具默认端口已避开）。
