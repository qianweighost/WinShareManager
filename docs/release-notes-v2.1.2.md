# WinShareManager v2.1.2 发布说明

> 修复：FTP 协议开关「启动/停止」均可能失败（0x800710D8）。

## 修复

### 1. FTP 开关停止失败：对象标识符没有表示一个有效的对象（0x800710D8）

- **现象**：v2.1.1 及之前，点击 FTP 卡片开关关闭时报错，FTP 服务停不下来；同样问题也会影响再次启动。
- **根因**：IIS 的 `Start-Website` / `Stop-Website`（以及 `appcmd start/stop site`）只对 HTTP/HTTPS 站点生效，它们走 W3SVC 通道；对 FTP 站点调用必然抛出 `0x800710D8 对象标识符没有表示一个有效的对象`。这是 IIS 的已知行为，FTP 站点必须经 `ftpServer` 对象控制（`(Get-Website).ftpServer.Start()/Stop()`）。
- **修复**：FTP 启动/停止全部改走 `ftpServer` 对象，FTPSVC/W3SVC 服务启动逻辑保留。

### 2. 新建共享路径未清洗首尾空白（潜在数据损坏）

- **现象**：若新增共享时粘贴的路径带换行/空格（如 `D:\共享\n`），会原样写入 IIS 虚拟目录配置，产生一个永不存在的物理路径对象，且该站点后续所有启停操作都会失败（本机已实际发生，vdir `ftp-9b1567d5` 的物理路径被写成了带换行的值）。
- **修复**：`New-ShareEntry` 入口对路径做 `Trim()`，脏路径再也进不了 IIS 配置。

## 升级说明

- 直接替换 exe 即可，配置自动保留。
- 若曾用带空格/换行的路径创建过共享，建议删除该共享后用干净路径重建一次（本机的问题路径已手工修复）。
